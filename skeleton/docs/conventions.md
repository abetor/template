# Documentation and state conventions

This file comes from `tool-template` and reaches child repositories through regeneration
diff. Editing it in place is an intentional fork and the reason should be recorded by the
child repository.

## Documentation

- The canonical four documents are `docs/VISION.md` (why), `docs/DESIGN.md` (architecture
  and reasons), `docs/STATUS.md` (observed behavior and verification), and `docs/tasks.md`
  (the agent queue). Before adding an overview document, find whether its content belongs in
  one of these four.
- Research and hints are dated artifacts named `<topic>-YYYY-MM-DD.md`. Do not overwrite
  them; a new investigation creates a new file because preserving history is cheaper than
  reconstructing it.
- Use `NN-` prefixes only for linear corpora meant to be read in sequence. Ordinary
  documents remain unnumbered so inserting one does not force renaming the rest.
- The README heading `## Agent-facing invocation contract` is canonical across generated
  repositories. It lets an external agent find the command contract without reading the
  entire repository.

## Generated and handwritten files

A generated file starts with `GENERATED by <generator>; do not edit manually` and changes
only through its generator. A manual edit to generated output is a process defect, not a
shortcut.

## State

- Machine state uses JSON or SQLite and is written through `shared/fs.atomic_write` to avoid
  partial state. Markdown is a human-readable rendering, never the source of truth; code
  must not parse Markdown state.
- Session capture is runtime state and must remain ignored by Git. Durable public decisions
  belong in the selected public documentation, not in private session transcripts.

## Rules and enforcement

- Apply a delta filter: a model already knows general textbook advice. Add a rule only when
  it states this repository's choice in a disputed practice, a recurring failure and its
  mechanism, or a non-obvious threshold with a source. Deliberately adding nothing is a
  valid result.
- A rule without a gate is a preference. A strict rule needs enforcement through a check,
  test, or linter, or an explicit statement that it relies on review.
- For each new wrapper, ask whether it still helps if the model becomes twice as capable.
  Scaffolding that only compensates for current model weakness is temporary and must be
  reviewed; scaffolding that communicates real system constraints remains.
- Numeric metrics such as coverage or test count are not sufficient gates by themselves.
  State the risk and the mechanism used to judge it.
- A secret-bearing configuration field stores an environment variable name, not its value.
  Resolve values at runtime and pass them to subprocesses through the environment, never in
  argv where process listings expose them. Ports, hosts, and paths are configurable; a
  literal may exist only as a documented fallback.
- CLI exit codes are 0 success, 75 quota, 111 transient failure, and 1 permanent,
  configuration, or usage failure. The contract does not use argparse's default exit 2.
  Build parsers with `shared/cliargs.ArgumentParser`, and test an invalid flag.
- Do not classify a broad range of external platform errors as permanent. Use an explicit
  allowlist of observed permanent cases and treat unknown cases as transient because losing
  work is more costly than an extra retry. Enforce both sides of the boundary, including
  unknown codes and transport failures without a code.

## Publishing a repository

Run secret scanning first, not last. Rotating a leaked credential and removing it from every
clone and cache costs more than checking before publication.

1. Scan the working tree and index with
   `python3 <template>/harness/run_checks.py --repo-root .`. The
   `repo/secrets-not-tracked` check covers sensitive storage filenames, known literal key
   formats, populated `.env.sample` entries, and nearby unignored `.env` files.
2. Scan Git history separately. The baseline check intentionally does not inspect old
   commits. Choose explicitly between publishing existing history, creating a fresh
   repository, and rewriting history.
3. Search for machine-specific absolute paths, personal identifiers, internal hosts, and
   names of private projects in documentation and configuration.
4. Keep runtime data outside the repository and ensure README provides a public-quality
   description, limitations, and keyless quick start.

A secret committed to Git is compromised. Rotate it before cleaning repository history.

## External strings in template and pattern languages

A title, filename, or other user-provided string is data, not a program. When inserted into
another mini-language it can silently change meaning and make a later step fail. Escape it
with that language's own mechanism instead of maintaining a custom list of dangerous
characters.

| Destination | Escape mechanism | Example failure without escaping |
|---|---|---|
| `%`-based output template | replace `%` with `%%` | `Top 100%(items)` is parsed as a template token |
| `Path.glob` or `fnmatch` | `glob.escape` | `[AB] Lesson` becomes a character class |
| regular expression | `re.escape` | punctuation matches unintended text |

Control characters such as a newline in a filename belong to the same class. Enforcement
must use a hostile name through the real engine: run the output template through the actual
library API and match a glob against a file created on disk. A custom imitation of the
engine does not test this failure mode.
